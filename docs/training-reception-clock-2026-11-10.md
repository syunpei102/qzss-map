# 通知だけ届き訓練表示が出ない問題

2026年11月10日（火）13:00の日向灘を震源とする公式EEW訓練通報で確認した．Cloud Runの受信ログと公開WebのWebSocketフレームには通報が存在し，訓練表示設定もONだった．しかし公開WebのactiveEventsは0件で，通報を直接renderReportへ渡すと描画された．

v1.12.3で追加した地図読込待ち時間の加算が，Date.now()からperformance.now()で得た受信時刻を引いていた．経過時間が巨大になり，受信通報を期限切れと誤判定した．通知はサーバー側の別経路なので届いていた．訓練だけでなく通常の通報にも影響する．加算する経過時間を同一ブラウザのperformance.now()同士の差へ修正した．

前回の描画検証はrenderReportへの直接投入で，WebSocket受信ハンドラーの時刻計算を通過していなかった．今回，実際のハンドラーから描画直前までを実行する回帰テストを追加し，通常・訓練，新着・再接続，有効時間境界と地図読込待ちを確認した．時計の基準が異なる値を明示的に与えている．

Node 139件，Python 13件，release:check，git diff --checkが成功．実受信した訓練通報を隔離ローカルサーバーのingestへ送信し，WebSocketで配信して描画する経路を別途検証する．本番への試験通報再送は行わない．
