# 独立したブラウザ用テストサイト

初回公開：2026年11月12日（木），v1.14.0．通常の本番マップ・受信機OTA・配信用VMとは別に配信する．

## 操作

`/test.html` で4つのパターンから選ぶ．選択画面を閉じて日本全体の地図へ戻り，10秒後に疑似受信する．南海トラフ想定は初回10秒後に緊急地震速報，さらに10秒ごとに震源情報・震度情報・津波警報を追加する．同じ発生時刻・震源座標を使い，1つの地震の続報として統合する．

中止・選び直す操作でタイマーと地図表示をリセットする．ケースの切替時に地図を再読み込みしない．全画面とはブラウザの表示領域全体で地図を表示することであり，OSの全画面モードを強制する操作ではない．

## 分離

### 本番との一致範囲

公開中の本番v1.13.1と，独立テストサイトの配信ファイルを照合した．`native-map.js`，`style.css`，`earthquake-fill.js`，`earthquake-identity.js`，`map-source-cache.js`，`report-geography.js`，`report-ttl.js`，`training-report-filter.js`，`information-settings.js`，`data/native-base-tiles.bin` はSHA-256が一致する．通常の公開マップとテスト画面はいずれも独自Canvas描画を使う．

`main.js` はテストモードの状態表示，WebSocket接続抑止，通知購読抑止，疑似データ受け渡し・リセットの分岐を追加しているため，ファイル全体のハッシュは異なる．ズーム・図形・マーカー・パネルの描画処理は変更していない．通常の本番受信経路とシステム全体が同一であるとは表現しない．手動テストは60秒の表示期限を使うため，実際の通報の長い有効期限や再送・通知・デコードの確認は別の統合試験が必要．

- 通報は合成したデコード済みJSON．RF受信や電文デコードの試験ではなく，地図・パネル・ズームの表示試験．
- テスト用iframeは実際のWebSocketを開かず，表示設定はローカルの固定値で返す．POSTなどの書込みと通知購読・計測送信を無効化する．
- 親フレーム・同一オリジン・ページごとのnonceが一致する操作のみ受け付け，全通報を強制的に `is_test_data: true` とする．テスト用スクリプトの読込失敗時もmain.jsはWebSocketへ接続しない．
- 通常画面のlocalStorageを変更しない．通常アクセス時にはテスト用bootstrapを読み込まず，従来の受信処理を使う．
- 独立サービスの `scripts/test-site-server.js` は静的ファイルだけを返す．ルートは `/test.html` へ移動し，受信APIを持たず，WebSocketの接続要求も拒否する．
- `/index.html?sandbox=1` がテスト内の地図．地図・表示処理は通常マップと同じコードを使用する．公開中の本番サービスへは今回の変更を反映しない．

## 検証

- Nodeテスト：隔離通信・親フレーム認証・強制テスト分類・通常画面への非干渉・4通報の整合性・静的サーバーの書込み拒否を確認．
- 実ブラウザ：最初の10秒間は未受信，続報の10秒間隔，同一地震への統合，中止後の未受信，Jアラートのテスト表示，スマートフォン表示，本番向けWebSocket・POSTが0件であることを確認．
- ローカル作業フォルダには未追跡のFIFO `qzss_pipe` があるため，サーバー起動を含む全体テストはFIFOのない隔離コピーで実行する．FIFOは変更・削除しない．

## 配備

コミット済みソースを一時ディレクトリへ展開し，そのコミットの `Dockerfile.test-site` をビルド用 `Dockerfile` として使用する．専用Cloud Runサービス `qzss-map-test` へ配備する．本番サービス `qzss-map` の環境変数・トラフィック・受信機OTAは変更しない．
