# 地域別ズーム・情報種別設定の要件と検査

2026年11月10日（火）．v1.13.0ローカル確認候補．ユーザーの目視確認が完了するまで公開・OTAを行わない．

## 要件

1. 日本周辺の緊急地震速報は，受信直後・自動表示とも，有効な震源と速報対象地域を同じ画角に収め，情報パネルとの重なりを避ける．深発地震の異常震域も含める．震央コードからの代表位置は初回受信でも利用可能にする．
2. 東京のみのEEWは，東京都全体のGeoJSONに含まれる小笠原などの遠方離島を理由に引かない．震源が離島側にある場合は震源を含むために引くのが正しい動作とする．東京・伊豆・小笠原は受信コードで区別できるため，島の予報区が指定された場合はその地域をカメラ範囲に反映する．東京地方・伊豆・小笠原の塗りつぶしも同じ予報区の形状を使用し，対象外の島や本土を着色しない．
3. 気象コード130010／130020／130030／130040を，同一都県という理由だけで同時にズームしない．広域の130000は4地域に展開し，個々に巡回する．解除も4地域へ反映する．単一の予報区内の全ての島は対象として維持する．
4. 気象情報（分類10）と火山情報（噴火警報8・降灰9）をそれぞれ独立して表示・通知ON/OFFでき，初期値は両方OFF．設定を永続化し，接続中の画面にも反映する．OFFにすると既表示の対象を除去し，ONにすると保存中の有効な通報を再取得する．地震・津波・洪水・J/Lアラートはこの設定の対象外．
5. 通報の受信・保存・レイテンシー計測はOFFでも継続する．通知は全体設定に従う．設定変更は既存の管理者認証経路と，ローカル専用のloopback同期経路に限定する．Piのクラウド設定同期にも追加する．
6. 100件の再利用可能な合成データを用意する．地域・深さ・震源位置・続報・解除・訓練・期限切れ・気象／火山のON/OFFを含め，期待結果を各データに記載する．実在の災害情報として本番へ送信しない．
7. ローカル確認画面で1件送信・連続再生・停止・リセット・設定変更ができるようにする．通常の表示リセットではサーバーも地図も再起動せず，同じ接続で通報を検証する．期限切れケースだけは保存受信時刻を遡らせた復元を使用する．起動後にURLを伝え，ユーザーの確認を待つ．

## 調査結果・変更箇所

- public/main.js：earthquakeDisplayBoundsは対象地域があると震源を除外していた．受信直後と自動表示はこの関数を共用する．
- public/main.js：mainLandBoundsにより東京本土だけのEEWでは離島のbboxを避けている．EEW_REGION_TO_PREFECTURE_IDSでは16・17・18等が全て都県13へまとめられるため，カメラには元コードの区分も保持する．
- public/main.js：weatherSitesForSamePrefectureとzoomToWeatherCodeが気象の同一都県を統合している．東京の区域は別巡回へ変更する．
- public/data/weather_regions.geojson：130010=東京地方，130020=伊豆諸島北部，130030=伊豆諸島南部，130040=小笠原諸島，130000=東京都．
- server.js・public/main.js・register_discord_commands.js：設定の保存，通知ゲート，設定配信，描画ゲート，管理コマンドを追加する．
- qzss-pi-package/read_legacy_dual.py：既存/configポーリングに新設定を追加する．適用確認とOTA配信を区別する．

## 検査

Node回帰テスト，Python受信機テスト，両地図描画方式での実WebSocket入力，狭い画面とスマートフォン幅での投影位置，初回参照表の遅延，OFF→ON／ON→OFFと再接続，100件の送信・期待結果を検証する．検査結果と制限は実施後に追記する．


## 本番調査で判明した問題への対応

- 時計計算の混在はv1.12.4で修正済み．本候補でもperformance.now()同士で経過時間を求める．実受信した公式訓練4電文を用い，通常扱い／公式訓練，期限境界を追加検査する．
- 震源は日本周辺の範囲にある有効なものを，EEWから観測震度・津波へ統合された後もカメラに含める．遠方地震の表示制限は維持する．
- 全47都県の震度アイコンはカメラと同じ主要地形の内部に置く．凹形と穴を持つ形状も検査する．
- 震央参照表をバックグラウンド取得し，取得成功時に有効期限内・未解決の震源だけを補う．明示座標を上書きせず，期限切れの震源は復活させない．取得失敗時は再試行する．
- 設定の初期値とHTTP失敗時は公式訓練OFF．設定取得は3秒で打ち切り，通常通報の処理を無期限に止めない．30秒後に再取得し，復旧時にONへ戻る種別は再接続で保存通報を再取得する．
- 表示結果はapplied（表示データ反映）／unchanged／skipped／errorとして理由・画面バージョンを保存する．除外通報には表示準備時間を付けない．画素の表示成功を証明する値とは区別する．先着のレイテンシーは維持し，別版・別判定は最大8件の追加確認として保存する．
- リセット・再接続では気象・その他のタイマーと保留データも破棄し，旧タイマーで新しい警報が消えたり，古い図形が再表示されたりしないようにする．
- app-version.jsはreleases.jsonから生成し，VERSION・紹介ページと同じrelease:sync/checkで同期する．既に旧版を読み込み済みのタブには，最初の一度の再読み込みが必要．本候補は未公開．


## 検証結果（ローカル候補）

- Node 183件・Python 13件成功，release:check・構文・差分チェック成功．Pi側の設定同期は別worktreeでPython 118件成功，未配信．
- 実受信した公式訓練4電文を実WebSocketハンドラー経由で再生し，候補版はON時に表示データへ反映，OFF時は全4件を除外し表示準備値を記録しないことを確認．旧v1.12.3の時計混在も同じ電文で再現し，修正後の回帰条件とした．
- 独自描画・MapLibre，1366×768／800×480／390×844，千島列島・深発地震の計12条件で受信直後・自動表示ともに震源と対象範囲が画面内かつパネル外に入ることを確認．参照表を遅延させた初回表示も含む．検査中に初回抑制時間内の補完後のカメラ再計算漏れを検出し，修正後に12条件を再実行して成功．
- 独自描画で100件を同じ地図・接続で処理し，通常ケースでページ再読み込みなし，表示・非表示の期待が全件一致．期限切れケースは保存受信時刻を遡らせるサーバー復元だけを行い，地図自体は再読み込みしない．
- 東京・鹿児島・沖縄を含む全47都県で，アイコン基準点が主要地形の範囲内かつ陸地内部にあることを検証．東京の画面外配置は両描画方式で解消．小笠原のみのEEWではカメラ範囲と着色形状が島側に一致することも確認．
- 設定失敗時の公式訓練OFF，有効期限・明示座標を尊重する震源補完，表示結果と版の検証・保存，重複計測値を保持した表示判定の追記を回帰テストで確認．
- 実端末のDia／iPhone Safariでの目視確認と本番・受信機への配信は未実施．ユーザー確認用のローカルサーバーを起動してURLを案内する．
