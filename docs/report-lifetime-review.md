# 表示期限の変更案

2026年11月13日（金）．v1.14.3のデプロイ前確認用．未デプロイ，OTA未配信．

| 情報 | 表示期限 | 地点ズームの優先保持 |
|---|---|---|
| 震源・震度 | 最後の受信から10分 | 10分 |
| 津波（国内警報・北西太平洋情報） | 最後の受信から20分 | 20分 |
| Jアラート | 最後の受信から20分 | 20分 |
| 緊急地震速報 | 従来の20分 | 従来の10分 |

取消・解除は期限を待たず処理する．公式訓練の20分，疑似データの1分，表示設定OFFは変更しない．ブラウザ再接続のreplay_age_msを表示・地点ズームの双方に適用し，接続し直しても期限をリセットしない．

## 受信機とサーバー

read_legacy.pyのsend_if_newは，同一電文を5分間抑止し，その後に衛星から再度受信したとき再送する．送信失敗は抑止履歴に入れない．サーバーの重複排除は10秒なので，この5分間隔の送信は状態のreceivedAtを更新し，ブラウザへ届く．特別なタイマーで過去電文を送り続ける実装は加えない．受信停止後も延々と期限が延びるためである．ハートビートのみでは災害情報の期限を延長しない．

5分は重複抑止の最小間隔であり，衛星から届かない間に送信を保証するものではない．実機の現在の稼働版・OTA適用状態はこの作業では照合していない．現行ソースに既にある処理なので，受信機コードの変更はなし．

## 検証

- FIFOを持たない分離コピーでNode.js全200件合格．本番送信なし．
- 10分・20分の期限境界，実受信による期限延長，再接続残寿命，取消，津波・Jアラートの20分ズームを追加確認．
- Python全体のテストはローカルのazarashi依存が未導入のため実行不可．実際のsend_if_new関数をASTで抽出し，299秒の重複抑止・300秒/600秒での再送・失敗直後の再試行を検証して合格．
- release:sync / release:check合格．公開前にコミット・CI・リビジョン確認等はRELEASING.mdに従う．


## v1.14.4で合意した変更

地震系は同じ内容の初回受信から10分．EEW→震源→震度の段階が進むと前段階を置き換え，後続情報自体の初回受信から10分．発生時刻や震央を使って地震を区別し，別の新しいEEWは前の震源・震度を退ける．津波沿岸線と点滅は優先ロックの対象外になっても残す．EEWの予測地域の塗りも10分に揃えた．津波・Jアラートの20分と，実RF受信時の5分再送はv1.14.3のまま．

サーバーはearthquake_first_receipts.jsonへ初回受信履歴を永続化する．期限後の同じ電文を再表示せず，過去の段階へ戻さない．初回受信からの経過時間をreplay_age_msとしてブラウザへ渡し，表示・ズーム・再接続で同じ期限を使う．履歴は48時間未受信で削除し，最大5000件．公式訓練・手動テストの従来設定は維持する．既存状態の移行時は保存済み受信時刻を引き継ぐが，これ以前に記録されなかった真の初回受信時刻を復元することはできない．

Node203件合格．隔離サーバーで期限切れ再受信，プロセス再起動，段階更新，新EEWと津波保持の実送受信テストも合格．本番への疑似電文送信なし．
